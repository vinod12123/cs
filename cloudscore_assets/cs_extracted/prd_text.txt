1. Executive Summary

ASTRA (Autonomous SRE & Threat Response Architecture) is CloudScore.ai&apos;s flagship 16-agent autonomous incident intelligence platform. Built on LangGraph, open-source LLMs via Ollama, and MongoDB Atlas, ASTRA unifies production telemetry, code context, infrastructure state, and runbook knowledge into a single continuously-learning system that detects, investigates, explains, and remediates incidents — autonomously and at production speed.



This PRD defines the full feature set, agent architecture, UI/UX flows, and API contracts required to build ASTRA&apos;s investigation engine, root cause analysis (RCA) module, recommendation system, and automated pull request (PR) generation pipeline — modeled on and extending the capabilities observed in Resolve.ai&apos;s product, with CloudScore&apos;s distinctive REI (Reliability Economics Intelligence) layer as a key differentiator.



Strategic Window

Competitive research confirms a 12–18 month window to own the "SRE + FinOps intelligence" category before hyperscalers close the gap. ASTRA&apos;s combination of autonomous investigation, financial impact quantification (REI), and open-source LLM architecture creates a moat that proprietary solutions like Resolve.ai, PagerDuty AIOps, and Datadog Bits AI cannot easily replicate.

6. Root Cause Analysis (RCA) Engine


6.1 RCA Architecture

The RCA engine consists of three agents working in sequence: the Planner/Hypothesis Agent (generates theories), Evidence Synthesis Agent (proves or disproves each), and the Critique Agent (quality gates the output). Together they produce a structured, evidence-backed root cause report with confidence scoring.




6.2 Confidence Scoring Model
Confidence Level
Score Threshold
Evidence Requirements

HIGH

≥ 80 points

3+ independent corroborating signal types (e.g., logs + metrics + code diff), clear causal chain from trigger to symptom, no contradictory evidence, Critique Agent approved

MEDIUM

50–79 points

2 corroborating signal types, plausible causal chain with one unconfirmed link, no strong contradictory evidence

LOW

< 50 points

1 signal type, causal chain has gaps or relies on inference, or contradictory evidence exists




6.3 RCA Report Structure (Right Panel)

The live report renders progressively as agents complete each section. Final structure:




Confidence Badge: Prominent pill showing HIGH / MEDIUM / LOW with color coding


Working Theory Headline: One-sentence bold summary of the root cause (e.g., "Deployment-triggered deadlocks from lack of lock ordering in batch update logic")


Root Cause Mechanism: Technical explanation of WHY the issue occurred, referencing specific code, queries, or config


Performance Impact Pattern: What metrics spiked, when, to what values — with inline mini-charts


Supporting Evidence (bulleted): Each bullet is a discrete, timestamped, linked evidence item with • dot for inline detail popup


Service Impact Assessment: Which services were affected, customer-facing vs internal, error rates, latency impact


Infrastructure Context: Resource state, recent changes, scaling events relevant to the incident


Recurring Schedule: Whether this incident pattern has occurred before (from Learning Agent memory)


Timeline: Chronological event sequence with GMT timezone label, event type tags (Query, Event, Deploy, Alert), and expandable detail per event


Suggested Next Steps: Ranked remediation actions ordered by risk and effectiveness




6.4 Evidence Reference System

Every metric value, timestamp, or technical claim in the RCA report is annotated with a clickable bullet dot (•) that opens an inline evidence card showing:


Raw data source (query, API call, or log entry that produced the value)


Exact timestamp and time window


Link to original data in Datadog, Grafana, CloudWatch, or GitHub


Confidence contribution score (how much this evidence raised/lowered the hypothesis score)

9. PR Generation Pipeline — Detailed Specification


9.1 PR Generation Workflow

The PR Generation Pipeline is the most technically complex ASTRA feature and a key differentiator. It uses CodeLlama 34B to produce production-quality code fixes informed by the complete RCA context.


Step
Agent
Action

1

Evidence Synthesis Agent

Identifies offending file(s), function(s), and line range(s) from RCA. Produces a precise code location reference: "packages/svc-entity-graph/src/db/event/postgres.ts lines 1331–1347"

2

Code & Deploy Agent

Fetches current file content from GitHub at the identified commit/branch. Extracts the exact problematic code block with surrounding context (±50 lines).

3

PR Generation Agent

Generates complete fixed code using CodeLlama 34B, informed by: root cause explanation, failing code block, error patterns from logs, performance requirements. Produces full before/after diff.

4

Critique Agent

Reviews the generated fix for: correctness (does it actually fix the root cause?), safety (no regressions introduced), style (matches codebase conventions), completeness (all affected code paths covered).

5

PR Generation Agent

If Critique passes: creates GitHub PR via API with structured PR description (see Section 9.2). If Critique fails: iterates up to 3 times before escalating to human.

6

Communication Agent

Posts PR link to Slack incident thread: "ASTRA has created PR #123 to fix the deadlock issue. Requires review from code owners."

7

Orchestrator

Adds PR URL to investigation report under "Suggested Next Steps". Updates plan status to reflect PR created. Monitors for PR merge to trigger investigation close.

12.1 REI Agent Calculations

ASTRA ROI: Monthly cost of incidents (pre-ASTRA baseline) vs. cost with ASTRA MTTR reduction — live ROI calculation

Configurable per-team confidence thresholds and action blacklists
